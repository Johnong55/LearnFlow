# Security policy

## Supported version

Security fixes are applied to the latest release on the `main` branch. Older
development snapshots are not supported.

## Reporting a vulnerability

Do not open a public issue for suspected vulnerabilities or exposed secrets.
Use GitHub's private vulnerability reporting feature for this repository. Add a
clear impact description, reproduction steps, and affected commit when known.

Do not include real credentials, personal data, access tokens, database dumps,
or production logs in the report. Revoke any credential that may have been
exposed before sharing sanitized evidence.

You should receive an acknowledgement within five business days. Confirmed
issues will be prioritized by exploitability and impact, fixed privately, and
disclosed after affected deployments can be updated.
